# Marwan SAT — Marwan Software Agents Team

**فريق برمجي من سبعة وكلاء ذكاء اصطناعي، بضوابط حتمية، يُثبَّت في أي مشروع.**

> الإصدار `0.1.0` — **تجريبي**. لم يمر بعد بالتجربة الأولى على مشروع حقيقي (الميثاق §17).
> [English summary](README.en.md) · الترخيص: [MIT](#الترخيص) © 2026 مروان أحمد
>
> **جديد على Antigravity أو على git؟** ابدأ من [دليل المبتدئين: تشغيل SAT في Antigravity خطوة بخطوة](docs/ANTIGRAVITY_GUIDE.md).

Marwan SAT ليس «وكيلاً أذكى». هو **نظام حوكمة** حول الوكلاء: مَن يكتب ماذا، ومتى، وبأي دليل، ومن يملك القرار. صُمّم على ثلاث قناعات:

- **ما يكتبه الوكيل عن عمله ليس دليلاً.** الدليل هو مخرجات الأدوات، وسجل Git، ونتيجة CI.
- **كاتب واحد للكود.** بقية الوكلاء يحللون ويراجعون ويهاجمون، لكنهم لا يكتبون الكود.
- **القرار لك.** بوابتان ثابتتان وبوابة مشروطة، والدمج بيدك وحدك عبر GitHub.

المرجع الكامل: [`charter/CHARTER.md`](charter/CHARTER.md).

## الفريق

| # | الدور | ماذا يفعل | ماذا لا يفعل |
|---|---|---|---|
| 1 | **المدير التقني** `tech-manager` | يستلم طلبك، ويدير المراحل، ويوزّع العمل، ويصعّد، ويقدّم التقرير | لا يكتب كوداً، ولا يتخذ قرارات تقنية، ولا يتجاوز فيتو |
| 2 | **مفسّر الطلب** `request-interpreter` | يحوّل طلبك إلى برومبت تنفيذي بقواعد وأمثلة محسوبة، ويسألك 3 أسئلة حاجزة كحد أقصى | لا يصمم |
| 3 | **المحلل والمعماري** `architect` | SPEC بمعايير قبول قابلة للاختبار، وARCH، وPLAN بملفات محددة لكل مهمة | لا يكتب كوداً ولا اختبارات |
| 4 | **المدقق الأمني** `security-auditor` | نموذج التهديدات قبل التصميم النهائي، ثم الهجوم على التطبيق محلياً بعد التنفيذ | لا يعدّل الكود، ولا يهاجم خارج localhost |
| 5 | **كاتب الاختبارات** `test-author` | يكتب الاختبارات **قبل** الكود من معايير القبول وحالات الإساءة | لا يلمس الكود |
| 6 | **المنفّذ** `implementer` | الكاتب الوحيد للكود، داخل الملفات المسموحة لمهمته فقط | لا يعدّل الاختبارات المجمّدة ولا المواصفات |
| 7 | **المراجع المعادي** `adversarial-reviewer` | يبحث عن أخطاء المنطق والمال والتلاعب بالاختبارات، بسياق نظيف | لا يقرأ تبريرات المنفّذ |

**والأدوات الحتمية** (Node.js فقط، بلا أي اعتماديات):

| الأداة | الدور |
|---|---|
| `phase` | آلة المراحل: لا انتقال إلا بشروط مكتوبة، وتُنشئ فرع المهمة وcommit تجميد الاختبارات |
| `verify` | تشغّل البناء والاختبارات والماسحات الأمنية، وتتحقق من سلامة الاختبارات والملفات المسموحة، وتحفظ الأدلة الخام |
| `report` | تبني التقرير من الأدلة مباشرة، وتختمه بـhash فلا يُجمَّل |
| `guard` | Hook لـAntigravity يرفض قبل التنفيذ أي كتابة خارج ما تسمح به المرحلة |

## دورة العمل

```text
طلبك ─► INTAKE ─► INTERPRET ─┬─► [البوابة 0: أسئلة حاجزة؟]
                             ▼
                          DESIGN ─► THREAT ─► ═البوابة 1: اعتماد التصميم═
                                                 │
                   TESTS (تجميد) ─► IMPLEMENT ─► REVIEW ─► REPORT ─► ═البوابة 2═ ─► دمج بيدك
                                       ▲            │ فيتو مؤكد
                                       └─── FIX ◄───┘  دورتان ثم تصعيد إليك
```

- **المسار الكامل** إلزامي لكل ما يمس المال، أو الصلاحيات، أو مخطط البيانات، أو المكتبات، أو نقاط الدخول من الخادم.
- **المسار الخفيف** للنصوص والواجهات فقط. إذا لمس مساراً حساساً، يرفضه `verify`.

|---|---|---|

| محرر Antigravity (IDE) | جزئي | الأدوات وCI. توثيقه لا يذكر الوكلاء المخصّصين، فتحدّث مع الفريق من التطبيق |
| Claude Code | مخطط له في 0.2.0 | الأدوات وCI |
| VS Code (Copilot) | مخطط له، ويستفيد من محوّل Claude Code لأنه يقرأ صيغته | الأدوات وCI |
| Cursor | غير مدعوم بعد | الأدوات وCI |
| Windsurf / Devin | غير مدعوم بعد | الأدوات وCI |

- **«الأدوات وCI» تعني:** أدوات `phase` و`verify` و`report` تعمل بـNode في أي طرفية، وworkflow الـCI يعمل على GitHub مهما كان محررك.

- **ما يعنيه «مدعوم»:** محوّل جُرّب على المنصة نفسها، لا مجرد تعليمات تثبيت.

## التثبيت

يُثبَّت SAT **في كل مشروع على حدة**، داخل مستودع git فيه commit واحد على الأقل. مستودع SAT نفسه لا يُعدَّل.

### الطريقة 1 — مباشرة من GitHub (الأسهل)

لا تحتاج إلى استنساخ SAT. من داخل مجلد مشروعك:

```bash
npx github:marwan-ahmed/marwan-sat#v0.1.0 init --stack nextjs
npx github:marwan-ahmed/marwan-sat#v0.1.0 doctor
git add -A && git commit -m "chore: install Marwan SAT 0.1.0"
```

- `--stack`: `nextjs` أو `laravel` أو `flutter` أو `react-native` أو `custom`. إن حذفته يحاول `init` اكتشافه من ملفات المشروع.
- `#v0.1.0` يثبّت الإصدار. بدونه تحصل على آخر نسخة في الفرع الرئيسي، وقد تتغير بين مشروع وآخر.
- **التحديث لاحقاً:** الأمر نفسه مع الوسم الأحدث وكلمة `update`، مثل `npx github:marwan-ahmed/marwan-sat#v0.2.0 update`.

### الطريقة 2 — استنساخ مرة واحدة، ثم الأمر `sat` في كل مشاريعك

مناسبة للاستخدام المتكرر، وللتطوير على SAT نفسه:

```bash
# مرة واحدة على جهازك
git clone https://github.com/marwan-ahmed/marwan-sat.git
cd marwan-sat
npm link                          # يجعل الأمر sat متاحاً في أي مجلد (لا اعتماديات تُثبَّت)

# في كل مشروع
cd /path/to/your-project
sat init --stack nextjs
sat doctor
git add -A && git commit -m "chore: install Marwan SAT 0.1.0"
```

- **التحديث:** `git pull` داخل مجلد `marwan-sat`، ثم `sat update` داخل المشروع.
- بدون `npm link`: استبدل `sat` بـ`node /path/to/marwan-sat/cli/sat.mjs`.

> **على Windows (PowerShell):** إن ظهر الخطأ `running scripts is disabled on this system` عند تشغيل `sat` أو `npx`، فالسبب سياسة التنفيذ الافتراضية في PowerShell، لا SAT. الحل: استخدم `sat.cmd` و`npx.cmd` بدلاً منهما، أو اسمح بالسكربتات المحلية لحسابك فقط بالأمر `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` ([توثيق Microsoft](https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_execution_policies)).

### ماذا يُنشئ `sat init`؟

- `.team/`: الميثاق، والأدوار، والقوالب، والمخططات، والأدوات، ونسخة من الترخيص، و`project.yaml` الخاص بمشروعك.
- `.agents/`: الوكلاء السبعة، والقاعدة الدائمة، ومهارات المكدس والأمن، والـhook.
- `.github/workflows/sat-verify.yml`: يشغّل `verify` على كل PR، والماسحات فيه إلزامية.

بعد التثبيت راجع `.team/project.yaml`: الأوامر، وأنماط الاختبار، والملف الأمني، وبيئة الهجوم.

## بدء العمل

> للشرح المفصّل خطوة بخطوة، مع المشكلات الشائعة وحلولها: [دليل المبتدئين](docs/ANTIGRAVITY_GUIDE.md).

لا يوجد أمر طرفية لبدء مهمة، **والمدير التقني هو من يفتحها**: يحفظ طلبك حرفياً، وينشئ فرع المهمة `sat/TASK-<n>`، ثم يوزّع العمل.

1. افتح مجلد المشروع في **تطبيق Google Antigravity** (التطبيق، لا المحرر IDE)، دون Worktree.
2. اختر **`tech-manager`** (المدير التقني) من قائمة **Main Agent** فوق مربع الكتابة.
3. أرسل له **أمر البدء**:

```text
مهمة جديدة: <اكتب طلبك كما تشرحه لمدير تقني بشري>
```

مثال:

```text
مهمة جديدة: أضف إلى لوحة الإدارة صفحة للأقساط المتأخرة أكثر من 30 يوماً، مع تصفية حسب الفرع وتصدير CSV.
```

**قبل أمر البدء:**
- يجب أن تكون شجرة العمل نظيفة، أي لا توجد تغييرات بلا commit.
- يجب ألا تكون هناك مهمة نشطة أخرى. SAT يعمل على مهمة واحدة في كل مرة.

**بعد أمر البدء** يعود إليك المدير التقني في ثلاث نقاط فقط:
- **البوابة 0** (إن وُجد غموض): أسئلة مغلقة، 3 كحد أقصى.
- **البوابة 1**: ملخص التصميم والملفات التي سيلمسها كل جزء. لا يُكتب سطر كود قبل موافقتك.
- **البوابة 2**: التقرير ورابط PR. ادمج بنفسك، أو اطلب تعديلاً.

**ردّك على البوابات** يكون بكلماتك في المحادثة نفسها: `موافق`، أو `عدّل: <ما تريد>`، أو `ألغِ المهمة`. يسجّل المدير التقني ردّك حرفياً في سجل المهمة.

في وضع `gates.approval: owner` تُسجَّل الموافقة بيدك من الطرفية، ويرفضها `guard` إن حاول وكيل تشغيلها:

```bash
node .team/bin/phase.mjs approve GATE_1 --decision approve --note "موافق"
```

**المتابعة في أي لحظة:** `node .team/bin/phase.mjs status`.

**بعد دمج كل مهمة، وقبل التالية:** `git checkout main` ثم `git pull`. يرفض SAT بدء مهمة من فرع مهمة سابقة.

## ما يضمنه SAT وما لا يضمنه

**يضمنه بأدوات لا يتحكم بها الوكلاء:**
- الاختبارات تُجمَّد بـcommit قبل الكود، وأي تعديل عليها بعده تكشفه `verify`.
- كل تغيير خارج `allowed_write` لمهمته تكشفه `verify`.
- ملفات القالب محمية بـchecksums.
- التقرير لا يُجمَّل: أقسامه المولّدة مختومة بـhash.
- الدمج بيدك عبر Branch protection.

**لا يضمنه، وبصراحة:**
- **`guard` خط دفاع أول لا أخير.** أمر طرفية يستطيع الكتابة في ملف دون المرور به. لهذا يبقى `verify` وCI هما الضمان.
- **البوابتان 0 و1 إجرائيتان في الوضع الافتراضي.** لفرضهما بالأداة: `gates.approval: owner`، وعندها تشغّل أمر الموافقة بنفسك.
- **المدقق الأمني لا يضمن الحماية من الاختراق.** بلا بيئة هجوم مُعدّة يكون حكمه `INCOMPLETE`، ولا يهاجم تطبيقات الهاتف نفسها في هذا الإصدار. اختبار الاختراق البشري قبل الإطلاق ما زال مطلوباً.
- **أسماء أدوات Antigravity** مأخوذة من توثيقه الرسمي، لكن افتح كل وكيل مرة بعد التثبيت للتأكد: اسم أداة خاطئ قد يعلّق الوكيل.
- **الميزانية** لا تُقاس آلياً بعد، لأن المنصة لا تتيح قراءة الاستهلاك.
