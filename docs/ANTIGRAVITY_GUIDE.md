# تشغيل Marwan SAT في Google Antigravity — دليل المبتدئين

> كُتب هذا الدليل لتطبيق **Antigravity 2.33.0** (نوفمبر 2026) على Windows، ويصلح لـmacOS وLinux مع تغيير صيغة المسارات.
> أسماء الأزرار والقوائم قد تتغير بين إصدارات Antigravity. إن لم تجد زراً بالاسم المذكور، فابحث عن أقرب اسم له.

---

## الصورة في دقيقة

- **SAT مجموعة ملفات تُضاف إلى مشروعك.** تحتوي سبعة وكلاء يظهرون داخل Antigravity، وأدوات صغيرة تراقب عملهم.
- **أنت تتحدث مع وكيل واحد فقط: المدير التقني** `tech-manager`. هو يوزّع العمل على الستة الباقين ويعود إليك بالنتيجة.
- **لا يُكتب سطر كود قبل موافقتك على التصميم**، ولا يدخل أي تغيير إلى الفرع الرئيسي إلا بدمجك أنت على GitHub.
- **الوقت المتوقع:** تجهيز الجهاز مرة واحدة (30–45 دقيقة)، ثم 5 دقائق لكل مشروع جديد.

> ### برنامجان من Antigravity، ولكل منهما دور
> - **المحرر (Antigravity IDE):** شاشة الكود المعتادة. استخدمه للطرفية، وgit، وقراءة الملفات والتقارير.
> - **التطبيق (Antigravity):** هنا تتحدث مع فريق SAT. توثيق Google الحالي يذكر الوكلاء المخصّصين في **التطبيق** و**سطر الأوامر** فقط، لا في المحرر.
>
> يمكن فتح المجلد نفسه في البرنامجين في الوقت نفسه.
>
> **تستخدم VS Code أو Cursor أو Windsurf أو Claude Code؟** الفريق لا يعمل فيها في هذا الإصدار. التفاصيل في جدول «دعم المنصات» في README.

## أين كل شيء في المحرر (Antigravity IDE)

الشاشة مقسومة ثلاثة أقسام:
- **يسار:** شجرة الملفات.
- **وسط:** الكود، وتحته لوحة سفلية فيها Terminal وProblems وOutput.
- **يمين:** لوحة الوكيل.

| تريد أن… | مكانه في المحرر |
|---|---|
| تفتح مجلد مشروع | قائمة **File** ← **Open Folder** |
| تفتح الطرفية | قائمة **Terminal** (أعلى الشاشة) ← **New Terminal**، أو تبويب **Terminal** في اللوحة السفلية |
| تعرف الفرع الحالي | أسفل يسار الشاشة، في شريط الحالة، يظهر اسم الفرع. **النجمة** (`main*`) تعني وجود تغييرات غير محفوظة |
| تنتقل إلى فرع آخر | اضغط اسم الفرع أسفل اليسار، ثم اختر الفرع من القائمة |
| تسحب آخر التحديثات من GitHub | زر المزامنة ⟳ بجانب اسم الفرع أسفل اليسار |
| تحفظ التغييرات (commit) | أيقونة **Source Control**، الثالثة في الشريط الأيسر، وعليها رقم عدد الملفات المتغيّرة |
| ترى الأخطاء | تبويب **Problems** في اللوحة السفلية، أو العدّاد ⓧ ⚠ في شريط الحالة |
| تُظهر لوحة الوكيل أو تخفيها | **Ctrl + L** |
| تبدأ محادثة جديدة | زر **+** أعلى لوحة الوكيل |
| تختار النموذج | أسفل مربع الكتابة، بجانب زر **+** (مثل `Gemini … High`) |
| تضيف ملفاً إلى سياق المحادثة | زر **+** أسفل مربع الكتابة، أو اكتب `@` ثم جزءاً من اسم الملف |
| تراجع تعديلات الوكيل | بطاقة **files changed** تحت ردّه ← زر **Review** |
| ترى القواعد والـhooks | زر **⋮** أعلى لوحة الوكيل ← **Customizations** |
| تفتح إعدادات الوكيل | كلمة **Antigravity** أسفل يمين الشاشة في شريط الحالة ← **Antigravity Settings** |

## الخطوة 1 — جهّز جهازك (مرة واحدة)

| الأداة | لماذا | التثبيت | التحقق |
|---|---|---|---|
| **Node.js 20 أو أحدث** (نسخة LTS) | أدوات SAT مكتوبة بـNode | [nodejs.org](https://nodejs.org) | `node -v` |
| **Git** | SAT يعمل بفروع وcommits | [git-scm.com](https://git-scm.com) | `git --version` |
| **تطبيق Antigravity** | مكان عمل الوكلاء | [antigravity.google/download](https://antigravity.google/download) | يفتح ويطلب تسجيل الدخول بحساب Google |
| **GitHub CLI** `gh` (موصى به) | ليفتح المدير التقني طلب الدمج (PR) بنفسه | [cli.github.com](https://cli.github.com) | `gh auth status` |

**أين أكتب هذه الأوامر؟** في الطرفية (Terminal) بإحدى طريقتين:
- **في المحرر:** قائمة **Terminal** ← **New Terminal**. تفتح الطرفية داخل مجلد المشروع مباشرة.
- **خارج المحرر:** افتح قائمة Start واكتب `Terminal` أو `PowerShell`.

**بعد تثبيت Git**، عرّف نفسك له مرة واحدة:

```bash
git config --global user.name "اسمك"
git config --global user.email "بريدك@example.com"
```

**بعد تثبيت gh**، اربطه بحسابك على GitHub:

```bash
gh auth login
```

> ### ⚠️ تأكد أن عندك التطبيق، لا المحرر وحده
> مثبّت Antigravity يضع عادة برنامجين على جهازك: **Antigravity** (التطبيق) و**Antigravity IDE** (المحرر).
> الحديث مع فريق SAT يكون في **التطبيق**. إن لم تجده، فنزّله من صفحة التحميل نفسها.
> حدّث البرنامجين إلى آخر إصدار، فالإصدارات القديمة فيها أخطاء معروفة تخص الوكلاء المخصّصين والـhooks.

## الخطوة 2 — جهّز مشروعك

يجب أن يكون المشروع **مستودع git فيه commit واحد على الأقل**، ويُفضّل أن يكون مرفوعاً على GitHub.

**مشروع جديد لم يدخل git بعد:**

```bash
cd D:\projects\my-app
git init
git add -A
git commit -m "first commit"
```

**مشروع موجود على GitHub:** تأكد أنك على الفرع الرئيسي وأنه محدّث:

```bash
cd D:\projects\my-app
git checkout main
git pull
```

> **اسم الفرع الرئيسي:** في المستودعات القديمة قد يكون `master` بدل `main`، وأي أمر في هذا الدليل يُكتب باسم فرعك. ولمعرفة الاسم بعد تثبيت SAT، انظر إلى `base_branch` في `.team/project.yaml`.

**موصى به:** فعّل حماية الفرع الرئيسي من إعدادات المستودع على GitHub، واشترط Pull Request قبل الدمج. بهذا لا يستطيع أي وكيل الدفع إلى الفرع الرئيسي مباشرة.

## الخطوة 3 — ثبّت SAT في المشروع

من داخل مجلد المشروع:

```bash
npx github:marwan-ahmed/marwan-sat#v0.1.0 init --stack nextjs
```

اختر قيمة `--stack` حسب مشروعك:

| مشروعك | القيمة |
|---|---|
| Next.js / React على الويب | `nextjs` |
| Laravel / PHP | `laravel` |
| Flutter / Dart | `flutter` |
| React Native / Expo | `react-native` |
| غير ذلك | `custom` |

> **على Windows:** إذا ظهر الخطأ `running scripts is disabled on this system`، فاكتب `npx.cmd` بدل `npx`.

**افحص الجاهزية:**

```bash
npx github:marwan-ahmed/marwan-sat#v0.1.0 doctor
```

**كيف تقرأ النتيجة:**
- `✓` جاهز.
- `!` تنبيه: يمكنك المتابعة، لكن اقرأه.
- `✗` عائق: أصلحه قبل المتابعة. الرسالة بجانبه تقول ما المطلوب.

**تأكد خصوصاً من هذا السطر:** `✓ guard يعمل على هذا الجهاز`. هو الحارس الذي يمنع الوكلاء من الكتابة خارج حدودهم.

**احفظ ملفات SAT في git:**

```bash
git add -A
git commit -m "chore: install Marwan SAT 0.1.0"
```

**بدون أوامر:** افتح أيقونة **Source Control** في المحرر، واكتب الرسالة في المربع أعلاها، ثم اضغط **Commit**.

> **لماذا الـcommit إلزامي؟** SAT يرفض بدء أي مهمة إذا وُجدت تغييرات غير محفوظة. هكذا يعرف بدقة ما غيّره الوكلاء وما كان قبلهم.
> العلامة السريعة: إن ظهرت نجمة بجانب اسم الفرع أسفل يسار المحرر (`main*`)، فهناك ما لم يُحفظ بعد.

## الخطوة 4 — افتح المشروع في Antigravity

1. افتح التطبيق، ثم من الشريط الجانبي اختر **Projects** ← **Create New Project** ← **New Project**.
2. اختر **مجلد المشروع نفسه**، أي المجلد الذي فيه `.team` و`.agents`. لا تختر المجلد الأعلى منه.
3. عند بدء المحادثة **لا تختر New Worktree**: اعمل على المجلد مباشرة. SAT ينشئ فروعه بنفسه، ويحفظ حالة المهمة داخل مجلد المشروع.

> **أشهر خطأ للمبتدئين:** فتح مجلد يحتوي عدة مشاريع، مثل `D:\projects` بدل `D:\projects\my-app`.
> Antigravity يبحث عن `.agents` في جذر المجلد المفتوح، فلا يجد الوكلاء ولا الحارس.

## الخطوة 5 — اضبط الصلاحيات

افتح **Settings** (أسفل يسار التطبيق) ← **General** ← **Global Permissions** ← **Permission Preset**، واختر:

| الخيار | متى | ملاحظة |
|---|---|---|
| **Default** ✅ | **الموصى به** | الأوامر تعمل داخل بيئة معزولة (sandbox) دون سؤالك، ويسألك قبل أي أمر يحتاج الخروج منها |
| **Request Review** | إذا لم يظهر Default | يحدث هذا على أجهزة Windows التي لا تدعم البيئة المعزولة. يسألك قبل **كل** أمر: نقرات أكثر، لكنه آمن |
| **Turbo** ❌ | **لا تستخدمه** | بلا بيئة معزولة، وبلا أي سؤال، ومع وصول إلى كل ملفات جهازك |

**طلبات الموافقة التي ستراها:** البيئة المعزولة بلا إنترنت، لذلك ستُطلب موافقتك على أوامر مثل:
- `node .team/bin/verify.mjs`: يحتاج الإنترنت لفحص المكتبات.
- `git push` و`gh pr create`: لرفع الفرع وفتح طلب الدمج.

**قاعدة الموافقة:** اقرأ الأمر قبل الضغط.
- **وافق** على أوامر `node .team/bin/…`، وأوامر مشروعك المعتادة (`npm …`، `php artisan …`، `flutter …`)، و`git push -u origin sat/TASK-…`، و`gh pr create`.
- **ارفض** أي أمر لا تفهمه، وأي حذف للملفات، و`git push --force`، وأي دفع إلى `main`، وأي أمر يعمل خارج مجلد مشروعك.

## الخطوة 6 — تأكد أن Antigravity يرى الفريق

1. **الوكيل:** في الشاشة الرئيسية لمدير الوكلاء (Agent Manager)، لا في اللوحة الجانبية للمحرر، تظهر قائمة **Main Agent** فوق مربع الكتابة. يجب أن تجد فيها **`tech-manager`**.
   الوكلاء الستة الآخرون **لا يظهرون في هذه القائمة، وهذا مقصود**: المدير التقني وحده يستدعيهم.
2. **الحارس:** افتح **Settings** ← **Customizations** ← **Hooks**، وتأكد أن `marwan-sat-guard` مفعّل.

> **وفي المحرر؟** لوحة الوكيل في المحرر فيها اختيار النموذج فقط، ولا يذكر توثيقها اختيار وكيل مخصّص.
> إن ظهر لك `tech-manager` فيها بعد تثبيت SAT، فاستخدمه وأبلغ عن ذلك في مستودع SAT ليُحدَّث هذا الدليل. وإن لم يظهر، فاعمل من التطبيق.

**إذا لم يظهر `tech-manager`:**
1. تأكد أنك فتحت مجلد المشروع نفسه (الخطوة 4).
2. حدّث Antigravity إلى آخر إصدار، ثم أعد تشغيله.
3. شغّل `doctor` مجدداً. إن قال إن ملفات الوكلاء معدّلة، فأعد توليدها:
   ```bash
   npx github:marwan-ahmed/marwan-sat#v0.1.0 regenerate --force
   ```

## الخطوة 7 — أول مهمة

1. ابدأ محادثة جديدة داخل المشروع، واختر **`tech-manager`** من قائمة **Main Agent**.
2. اختر نموذجاً قوياً للمحادثة. المدير التقني يعمل بنموذج المحادثة، والوكلاء الآخرون محدّدة نماذجهم مسبقاً.
3. اكتب **أمر البدء**:

```text
مهمة جديدة: <اكتب طلبك كما تشرحه لمدير تقني بشري>
```

**طلب جيد يجيب عن أربعة أسئلة:** ماذا تريد؟ لمن؟ ما الذي يجب ألا يتغير؟ كيف تعرف أنه نجح؟

```text
مهمة جديدة: أضف إلى لوحة الإدارة صفحة تعرض الأقساط المتأخرة أكثر من 30 يوماً.
يراها موظفو الفروع فقط، وكل موظف يرى فرعه وحده.
لا تغيّر طريقة حساب الأقساط الحالية.
النجاح: الصفحة تعرض اسم المقترض والمبلغ وعدد أيام التأخير، مع تصدير CSV.
```

> **نصيحة للتجربة الأولى:** ابدأ بمهمة صغيرة وقليلة المخاطر، مثل تعديل نص أو تحسين شكل صفحة. تتعلم بها الدورة كاملة قبل أن تعطي الفريق شيئاً يمس المال أو الصلاحيات.

## الخطوة 8 — ماذا يحدث بعد أمر البدء، وما المطلوب منك

| المرحلة | من يعمل | ماذا ترى | ماذا تفعل |
|---|---|---|---|
| فهم الطلب | مفسّر الطلب | أحياناً **3 أسئلة كحد أقصى** (البوابة 0) | أجب عنها بوضوح |
| التصميم والتهديدات | المعماري والمدقق الأمني | **ملخص التصميم** والملفات التي ستتغير (البوابة 1) | اقرأه، ثم اكتب: `موافق`، أو `عدّل: …`، أو `ألغِ المهمة` |
| الاختبارات ← التنفيذ ← المراجعة | كاتب الاختبارات، فالمنفّذ، فالمراجع والمدقق | تقدّم العمل، وطلبات موافقة على أوامر | وافق على الأوامر بحسب قاعدة الخطوة 5 |
| التقرير | المدير التقني | مسار `REPORT.md` ورابط PR (البوابة 2) | اقرأ القسم 1 من التقرير، ثم **ادمج بنفسك على GitHub** أو اطلب تعديلاً |

**قواعد يجب أن تعرفها:**
- **سكوتك ليس موافقة.** المدير التقني ينتظر رداً صريحاً منك في كل بوابة.
- **الفيتو حقيقي.** إذا وجد المراجع أو المدقق مشكلة خطيرة مؤكدة، يعود العمل إلى الإصلاح دورتين كحد أقصى، ثم يُعرض الأمر عليك.
- **التصعيد يعني أن القرار لك.** يكتب لك المدير التقني ما حدث والدليل وخيارين على الأقل مع توصيته. اختر بكلماتك.

## الخطوة 9 — بعد الدمج، وقبل المهمة التالية

بعد أن تدمج طلب الدمج (PR) على GitHub، ارجع إلى الفرع الرئيسي وحدّثه:

```bash
git checkout main
git pull
```

**بدون أوامر، من المحرر:**
1. اضغط اسم الفرع أسفل يسار الشاشة، واختر `main`.
2. اضغط زر المزامنة ⟳ بجانبه.

SAT يرفض بدء مهمة جديدة وأنت ما زلت على فرع مهمة سابقة، حتى لا تُبنى مهمة على كود لم يُدمج بعد.

---

## أوامر قد تحتاجها

تُكتب كلها في الطرفية من داخل مجلد المشروع:

| الأمر | متى |
|---|---|
| `node .team/bin/phase.mjs status` | لتعرف أين وصلت المهمة الحالية |
| `npx github:marwan-ahmed/marwan-sat#v0.1.0 doctor` | عند أي شك في التثبيت |
| `node .team/bin/phase.mjs cancel --note "السبب"` | لإلغاء المهمة الحالية نهائياً |
| `git checkout main` ثم `git pull` | بعد كل دمج، وقبل كل مهمة جديدة |

## مشكلات شائعة وحلولها

| الرسالة أو العَرَض | السبب | الحل |
|---|---|---|
| `running scripts is disabled on this system` | سياسة PowerShell الافتراضية تمنع السكربتات | استخدم `npx.cmd`، أو شغّل مرة واحدة: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `tech-manager` لا يظهر | مجلد خاطئ، أو إصدار قديم من Antigravity | راجع الخطوتين 4 و6 |
| «شجرة العمل غير نظيفة» | تغييرات غير محفوظة في git | احفظها بـ`git add -A` ثم `git commit -m "…"`، أو أجّلها بـ`git stash` |
| «أنت على فرع مهمة سابقة» | لم ترجع إلى الفرع الرئيسي بعد الدمج | `git checkout main` ثم `git pull` |
| «توجد مهمة نشطة» | مهمة سابقة لم تُغلق | أكملها، أو ألغِها بأمر `cancel` |
| `Please tell me who you are` عند commit | git لا يرى هويتك من داخل البيئة المعزولة | نفّذ أمري `git config` من الخطوة 1 داخل مجلد المشروع، **بدون** `--global` |
| طلبات موافقة متكررة على `verify` | يحتاج الإنترنت، والبيئة المعزولة بلا إنترنت | هذا طبيعي: اقرأ الأمر ووافق |
| وكيل متوقف بلا تقدم لفترة طويلة | غالباً اسم أداة لا يعرفه إصدار Antigravity لديك | حدّث Antigravity، وأبلغ عن المشكلة في مستودع SAT مع رقم الإصدار |
| `verify` فشل مرتين متتاليتين | SAT يوقف العمل ويصعّد إليك تلقائياً | اقرأ رسالة التصعيد واختر أحد الخيارات |

## ما يجب ألا تفعله

- **لا تعدّل ملفات `.team/` و`.agents/` يدوياً**، باستثناء `.team/project.yaml`. SAT يكشف التعديل ويوقف العمل.
- **لا تدمج قبل قراءة التقرير.** القسم 1 فيه القرارات التي تحتاج انتباهك.
- **لا تستخدم Turbo**، ولا توافق على أمر لا تفهمه.
- **لا تعطِ الوكلاء بيانات حقيقية:** لا بيانات عملاء، ولا كلمات مرور، ولا مفاتيح إنتاج. الاختبار والتدقيق الأمني يعملان ببيانات اصطناعية فقط.
